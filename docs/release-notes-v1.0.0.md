# ServiceCenter v1.0.0 — примітки до випуску

Перша перевірена версія системи обліку замовлень сервісного центру. Випуск реалізує базову лінію вимог `requirements-baseline-v1.0` (ЛР №3).

## Реалізовані можливості

* **UC-01** — реєстрація клієнта, пристрою та замовлення з призначенням інженера. Дублікат активного серійного номера відхиляється, а повідомлення містить номер активного замовлення (FR-01, FR-02).
* **UC-02** — фіксація діагностики та додавання робіт/деталей з автоматичним перерахунком `TotalCost`. Кількість ≤ 0 і ціна < 0 відхиляються (FR-03).
* **UC-03** — послідовна зміна статусів `Accepted → InProgress → Ready → Issued` (а також `Ready → InProgress` при додатковій несправності) з історією переходів. Редагування після видачі блокується (FR-04).
* **UC-04** — пошук за номером замовлення, фільтр за статусом та електронна квитанція (FR-05).
* Вебінтерфейс (`http://localhost:5080`) і консольний клієнт, який проганяє контрольний сценарій приймання.

## Умови запуску

* .NET 9.0 Runtime (ASP.NET Core Runtime 9.0).
* Сервер запускається з каталогу `server` пакета: `cd server` → `dotnet ServiceCenter.Api.dll --urls http://localhost:5080`.
* Клієнт: `dotnet ./client/ServiceCenter.Client.dll`; адреса сервера задається змінною `API_BASE_URL` (за замовчуванням `http://localhost:5080`).

Докладна інструкція — у `README.md`.

## Відомі обмеження

* **Дані зберігаються лише в оперативній пам'яті серверного процесу.** Після зупинки або перезапуску сервера всі клієнти, пристрої, замовлення, позиції ремонту й історія статусів втрачаються. Після перезапуску лишається тільки початковий список із двох інженерів. Збереження в SQLite, передбачене SRS, відкладено до наступної версії.
* Кожна реєстрація створює новий запис клієнта; пошуку наявного клієнта за телефоном немає.
* Захист від одночасних запитів (`lock`) діє в межах одного серверного процесу.
