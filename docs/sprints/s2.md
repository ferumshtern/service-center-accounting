# Спринт S2 — гарантійне звернення та пошук за телефоном

## План

**Мета S2:** менеджер оформлює гарантійне звернення за виданим замовленням у межах 90 днів, а нове гарантійне замовлення та запис звернення зберігаються разом; замовлення клієнта можна знайти за номером телефону.

**Відібрані історії:** #17 «Гарантійне звернення» (оцінка: 8 SP); #8 «Пошук замовлення за телефоном клієнта» (оцінка: 5 SP, переоцінено в S2).

**ID задач і виконавці:**

| Задача | Виконавець | Результат | Перевірка |
| :--- | :--- | :--- | :--- |
| #18 Правило гарантії, служба гарантійного звернення та збереження | Лавренюк Серафим | `Rules/WarrantyRule.cs` і `WarrantyRuleTests`; `WarrantyService` (контекст через конструктор), таблиця `WarrantyClaims`, міграція `AddWarrantyClaims`, `POST /api/orders/{id}/warranty-claims`, оновлені діаграми | тести правила: 0, 89, 90 днів — гарантія; 90 днів + 1 хв і 91 день — ні; звернення раніше видачі — виняток; міграція на копії бази S1 зі збереженням записів; успішне й невдале (тригер) збереження двох записів; рецензія Євгенії |
| #19 Пошук за телефоном і клієнтські дії S2 | Головань Євгенія | параметр `phone` у `GET /api/orders`, тест пошуку, кроки 14–18 консольного клієнта, поле телефону та форма гарантійного звернення у вебінтерфейсі, README | критерії обох історій через клієнт; читання після перезапуску; рецензія Серафима |

**Залежності:** клієнтські дії гарантії (задача 2) починаються після злиття задачі 1 — потрібні служба, таблиця й маршрут. Пошук за телефоном від гарантії не залежить.

**Умови готовності:** виконано критерії приймання обох історій; модульні тести правила проходять; атомарність збереження перевірено на копії бази; зміни злиті в `main` через запит на злиття; CI успішний; код перевірив інший учасник; діаграми й README відповідають коду.
